# 온보딩 보강 기획

## 목표

- **Problem:** 첫 실행 사용자는 추천 항목을 고르고 첫 Pray를 적을 수 있지만, 온보딩에서 자기 항목을 만들 수 없고 알림 설정은 완료 후 별도 설정 화면에서 찾아야 한다.
- **Target User:** Praylist를 처음 실행해 자기 관심사를 분류하고 첫 기도 제목을 기록하려는 신규 사용자.
- **Goal:** 신규 사용자가 추천 항목 또는 직접 만든 항목에 첫 Pray를 저장하고, 원할 때 알림까지 설정한 뒤 노트로 진입하도록 한다.
- **Success Metric:** 검증 시나리오에서 첫 Pray 저장은 정확히 1회, 알림 허용·거부·건너뛰기 경로는 3/3 노트 도달, 앱 재시작 재개는 1/1 Pray 중복 생성 없이 완료한다.
- **Non-goals:** 계정, 서버/클라우드 저장, 첫 Pray 생략, 알림 권한 강제, 기도 내용 분석 전송, 기존 항목 관리/알림 기능 재구현.

## 현재 구현

- **현재 구조:** `OnboardingView`는 추천 항목 선택과 첫 Pray 작성의 2단계 화면을 제공한다. `CategoryManagerView`는 설정의 항목 생성·편집, `ReminderSettingsView`는 매일 알림을 담당한다.
- **처리 흐름:** 사용자가 추천 항목을 선택하고 첫 Pray 목적지와 제목을 입력한다. `PrayStore.finishOnboarding`이 항목과 첫 Pray를 저장하고 `onboarded`를 설정하면 루트 화면이 노트로 전환한다. 알림은 온보딩 밖 설정 화면에서 `ReminderService`로 예약한다.
- **사용 기술/구성요소:** SwiftUI, `@Observable @MainActor PrayStore`, `PrayData`/`PrayCategory`/`Pray`, JSON 원자 저장, UserNotifications 기반 `ReminderService`, 한국어·영어 리소스.
- **제약 또는 문제점:** `PrayData` 스키마 v1, 항목 이름 1–24자, 설명 최대 100자, Pray 제목 1–80자, 항목당 Pray 최대 10개다. 온보딩에서 사용자 항목 생성과 선택형 알림 단계를 제공하지 않는다. 첫 저장 직후 앱이 종료되면 기존 `onboarded` 값으로 온보딩을 건너뛰므로 알림 단계 재개 상태가 없다.

## 사용자 흐름

1. **진입 →** 신규 사용자가 앱을 연다. **시스템 반응 →** 추천 항목 선택을 표시한다.
2. **사용자 행동 →** 추천 항목을 선택하거나 `나만의 항목 만들기`를 누른다. **시스템 반응 →** 이름·설명·상징을 입력받아 검증하고 유효한 항목을 선택 목록에 더한다.
3. **사용자 행동 →** 선택 항목 중 목적지를 고르고 첫 Pray 제목을 입력한다. **시스템 반응 →** 제목 길이와 공백을 검사하고 유효한 입력에만 진행 버튼을 활성화한다.
4. **사용자 행동 →** 저장을 누른다. **시스템 반응 →** 중복 제출을 막고 `PrayStore`를 통해 항목과 첫 Pray를 저장한다. 실패하면 입력을 보존하고 오류/재시도를 표시한다.
5. **다음 행동 →** 저장 성공 후 사용자가 알림 시각을 고르고 `알림 켜기` 또는 `지금은 건너뛰기`를 선택한다. **시스템 반응 →** 켜기를 눌렀을 때만 OS 권한을 요청하고, 허용되면 반복 알림을 예약한다.
6. **목표 달성 →** 예약이 성공하거나 사용자가 거부/건너뛰기를 선택한다. **시스템 반응 →** 선택을 저장하고 노트로 이동한다. 알림 단계에서 앱을 종료했다면 다음 실행 시 해당 단계를 재개한다.

## 규칙과 예외 처리

유형: `BR` 비즈니스 규칙, `VR` 검증 규칙, `AR` 권한 규칙, `SR` 보안 규칙, `ER` 예외 규칙.

| ID | 조건 | 허용/제한 동작 | 예외 발생 시 처리 | 사용자에게 보이는 결과 |
| --- | --- | --- | --- | --- |
| BR-ONB-01 | 첫 실행 중 | 첫 Pray 저장은 필수, 알림 설정은 선택으로 둔다. | 알림 거부/건너뛰기가 온보딩 완료를 막지 않는다. | 알림 여부와 관계없이 노트에 도달한다. |
| BR-ONB-02 | 항목 선택 단계 | 추천 항목 하나 이상 또는 새 항목을 선택해야 다음으로 간다. | 선택이 0개면 다음 버튼을 비활성화한다. | 항목 선택이 필요함을 확인할 수 있다. |
| BR-ONB-03 | 첫 Pray 목적지 선택 | 선택한 항목에 Pray를 저장한다. | 대상 항목이 제거되면 남은 선택 중 하나로 바꾸고, 없으면 진행을 막는다. | 저장할 항목 이름을 확인할 수 있다. |
| VR-ONB-01 | 새 항목 생성 | 이름 1–24자, 설명 최대 100자, 지원 symbol만 허용한다. | 공백/초과 길이/미지원 symbol은 저장하지 않는다. | 해당 입력 오류와 보존된 초안을 본다. |
| VR-ONB-02 | Pray 제목 저장 | 공백을 정리한 제목 1–80자만 허용한다. | 빈 제목 또는 공백만인 제목을 거부한다. | 제목 오류가 표시되고 입력은 유지된다. |
| BR-ONB-04 | 선택 항목에 Pray가 이미 10개 | 추가를 제한한다. | 용량 초과를 저장 시 검출하면 항목 변경 또는 노트 진입을 제공한다. | 가득 찬 이유와 다음 행동을 본다. |
| ER-ONB-01 | 저장 버튼 연속 탭/저장 중 | 요청은 한 번만 실행한다. | 처리 중 입력을 잠그고 중복 탭을 무시한다. | 진행 상태가 보이고 중복 Pray는 생기지 않는다. |
| ER-ONB-02 | JSON 저장 실패 | 메모리 상태도 성공으로 바꾸지 않는다. | 입력을 보존하고 재시도를 허용한다. | 저장 실패 안내와 재시도 버튼이 보인다. |
| AR-ONB-01 | 알림 선택 전 | OS 권한 요청은 사용자가 `알림 켜기`를 누를 때만 한다. | 거부 후 반복 권한 요청을 하지 않고 건너뛰기 경로를 유지한다. | 권한 없이도 사용 가능하고 설정에서 다시 켤 수 있음을 본다. |
| BR-ONB-05 | 알림 시각 선택 | 현지 시·분으로 반복 예약한다. | 권한/예약 실패 시 알림 활성 선호를 저장하지 않는다. | 실패 이유와 노트로 계속하기를 본다. |
| ER-ONB-03 | 예약 성공 후 선호 저장 실패 | 예약과 저장 상태를 일치시킨다. | 이전 예약을 복구하고 재시도/건너뛰기를 제공한다. | 설정 실패가 표시되고 Pray는 유지된다. |
| SR-ONB-01 | 단계 재개 상태 저장 | Pray 내용은 기기에만 저장하고 진행 상태는 최소 로컬 UI 상태로 저장한다. 백업 schema v1은 변경하지 않는다. | 로컬 상태가 없거나 손상되면 `PrayData.onboarded`를 기준으로 안전한 화면을 연다. | 저장된 Pray를 잃지 않고 노트 또는 알림 단계로 이어진다. |
| BR-ONB-06 | 알림 건너뛰기 | 알림을 비활성 상태로 두고 완료한다. | 없음. | 노트에 도달하고 설정에서 나중에 켤 수 있다. |

## 구현 영역

### 포함 범위 (In Scope)

- 온보딩에서 사용자 항목을 생성·선택하고 첫 Pray에 연결한다.
- 첫 데이터 저장 뒤 선택형 알림 단계, 로컬 재개 상태, 거부/실패/건너뛰기를 구현한다.
- 한국어·영어, Dynamic Type, VoiceOver, Reduce Motion을 지원한다.

### 제외 범위 (Out of Scope)

- 계정, 서버/클라우드 동기화, 원격 분석, 알림 내용 개인화.
- 첫 Pray 생략 및 설정 화면 전면 재설계.
- `PrayData` schema 변경. 필요하면 별도 migration 계획을 작성한다.

### 구현 단위와 관련 시스템/레이어

- `Praylist/Views/OnboardingView.swift`: 단계, 사용자 항목 입력, 목적지 선택, 첫 Pray 입력, 알림 선택 UX.
- `Praylist/Views/CategoryManagerView.swift`: 항목 입력/검증 UI 재사용을 검토한다. 불가하면 공통 입력 뷰를 `Praylist/Views/`에 둔다.
- `Praylist/Services/PrayStore.swift`: 첫 데이터의 단일 저장 경계, 검증, 실패 원자성. 다른 계층에서 `PrayData`를 쓰지 않는다.
- `Praylist/Services/ReminderService.swift`: 권한 요청, 현지 시각 예약, 예약 rollback.
- `Praylist/Models/PrayData.swift`: 기존 필드/길이/용량 규칙만 소비하고 schema v1은 유지한다.
- `Praylist/Resources/ko.lproj/Localizable.strings`, `Praylist/Resources/en.lproj/Localizable.strings`: 화면과 오류 문구.
- `Praylist/App/PraylistApp.swift` 및 실제 루트 화면 상태 파일: `setupPending` 등 로컬 재개 상태를 구현하고 `onboarded`와 분리한다.
- `PraylistTests/PrayStoreTests.swift`, `PraylistUITests/PraylistUITests.swift`: 저장 계약 및 흐름의 Given/When/Then 검증.

## 완료 기준

### 기능·규칙·예외 완료

- 신규 사용자가 추천/직접 만든 항목에 첫 Pray를 저장하고 노트에 진입한다.
- 알림 허용·거부·예약 실패·건너뛰기 모두 Pray를 유지하고 중복 없이 노트로 이동한다.
- 항목/제목 검증, `PrayStore` 단일 쓰기, 명시적 권한 요청, schema v1 유지 규칙을 만족한다.
- 저장 실패, 재시작, 10개 용량 초과가 입력 손실이나 거짓 성공을 만들지 않는다.
- 한국어/영어, 큰 글자, VoiceOver, Reduce Motion 검증을 완료한다.

### 테스트용 완료 기준 (Given / When / Then)

- **Given** 항목 선택 화면에서 하나가 선택된 상태, **When** 사용자가 마지막 선택을 해제하면, **Then** 다음 버튼은 비활성화되고 선택 필요 상태가 접근성으로 읽힌다.
- **Given** 유효한 항목 선택 화면, **When** 사용자가 유효한 이름·설명·symbol의 새 항목을 생성하면, **Then** 새 항목이 선택 목록에 나타나 첫 Pray 목적지로 선택할 수 있다.
- **Given** 이름이 공백이거나 제한을 넘는 새 항목, **When** 저장을 누르면, **Then** 생성되지 않고 오류/입력이 유지된다.
- **Given** 유효한 항목과 제목, **When** 시작을 한 번 누르면, **Then** 해당 항목에 Pray가 정확히 하나 저장되고 알림 단계가 열린다.
- **Given** 저장 실패를 주입한 저장소, **When** 시작을 누르면, **Then** 다음 단계로 이동하지 않고 초안과 재시도 안내가 남는다.
- **Given** 알림 단계에서 앱이 종료된 상태, **When** 다시 실행하면, **Then** 선택 단계가 재개되고 기존 Pray는 중복되지 않는다.
- **Given** OS 권한 미결정, **When** 사용자가 건너뛰면, **Then** 권한 요청 없이 알림은 꺼진 상태로 노트에 도달한다.
- **Given** OS 권한 미결정, **When** 사용자가 알림 켜기를 누르면, **Then** 그때만 권한을 요청하고 허용 시 예약 후 노트에 도달한다.
- **Given** OS 권한 거부, **When** 사용자가 켜기를 시도하면, **Then** 활성으로 표시하지 않고 설정 안내/노트로 계속하기가 보인다.
- **Given** 예약 성공 뒤 설정 파일 쓰기가 실패, **When** 완료 처리를 하면, **Then** 이전 예약이 복구되고 Pray는 남으며 실패 안내가 보인다.
